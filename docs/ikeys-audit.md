# Аудит iKeys и решение по онлайн-записи

Дата: 2026-11-02. Статус: предварительная оценка, интеграция не подтверждена.

## Известно
- В прототипе используется адрес https://kzid-ekaterinburg.ikeys.pro/ (необходимо подтвердить у клиента).
- По сообщению клиента в текущем интерфейсе видны лишние шаги «ОМС / ПЛАТНО», выбор одного адреса, неудобный переход в WhatsApp.
- У клиники только платный приём и один адрес (со слов клиента).

## Не подтверждено
- Название компании-владельца iKeys, договор и тариф.
- Есть ли REST API, webhooks, deeplinks и доступ к свободным слотам.
- С какой МИС или CRM синхронизируются записи и кто ведёт расписание.
- Можно ли отключить ОМС, филиал, лишние контакты через административные настройки.
- Условия обработки и хранения персональных данных.

## Варианты
1. Настроить существующий iKeys: предпочтительно, если лишние шаги отключаются и запись корректно попадает в расписание.
2. Собственный UI + API iKeys/МИС: предпочтительно при наличии документированного API, разрешения поставщика и безопасной серверной интеграции.
3. Квиз-заявка + администратор: резервный вариант без доступа к слотам. Нельзя обещать пациенту подтверждённое время.

## Рекомендуемый следующий шаг
Попросить у клиента скриншоты настроек iKeys и контакт технической поддержки. Получить документацию API/виджета, описание МИС и действующий договор/тариф (без паролей и персональных данных). Проверить отключение ОМС и филиала, прямые ссылки на запись к врачу и стоимость интеграции.

## Безопасность
Не собирать в статическом GitHub Pages-прототипе медицинские данные и телефоны. Для реальной формы потребуются серверная часть, защищённая передача, корректные согласия и соблюдение применимых требований к персональным данным.
